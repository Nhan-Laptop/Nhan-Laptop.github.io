# AGENTS.md

This repository is a static personal blog for `nhan-laptop.github.io`.

The main purpose of this file is to help future agents understand what is manual, what is generated, and how to safely update the site without breaking the current workflow.

## 1. Project overview

- The site is a static HTML/CSS/JS blog.
- Markdown source posts live in `posts/*.md`.
- Generated article pages live beside them as `posts/*.html`.
- A custom Node build script converts Markdown into HTML using `marked`, `highlight.js`, and `KaTeX`.
- The blog currently focuses on:
  - CTF writeups
  - cryptography learning notes
  - personal/life posts

There is no framework here. Do not assume Next.js, Astro, Jekyll, Hugo, or Eleventy.

## 2. Important files

- `build.js`
  - Main build pipeline.
  - Reads all Markdown files in `posts/`.
  - Renders HTML into the shared writeup template.
  - Copies vendor CSS assets for syntax highlighting and KaTeX.
  - Regenerates `categories/writeup.html`.

- `package.json`
  - Build entrypoint is:
    - `npm run build:n1ctf`

- `templates/writeup-template.html`
  - Shared HTML template used for generated post pages.
  - The build script injects the rendered article into this template.

- `templates/category-template.html`
  - Category page layout template, if present.
  - If missing, the build falls back to reusing the existing `categories/writeup.html`.

- `index.html`
  - Homepage.
  - The `Latest Posts` section is currently manual, not auto-generated.

- `categories/writeup.html`
  - Auto-generated by `build.js` from posts whose source filename starts with `writeup-`.

## 3. Current content model

The current build logic treats posts differently depending on what metadata exists.

### Markdown frontmatter

`build.js` supports YAML frontmatter at the top of Markdown files:

```yaml
---
date: 2026-07-13
summary: Short summary shown in hero/category cards.
tags:
  - crypto
  - ckks
---
```

Supported frontmatter keys:

- `date`
- `summary`
- `tags`

The build script normalizes tags into `#tag` format for generated metadata blocks and category cards.

### Legacy metadata

The build also still supports older inline metadata patterns such as:

- `Date: ...`
- `Tags: ...`
- `Summary: ...`

Frontmatter takes priority when both exist.

## 4. How the build works

When `npm run build:n1ctf` runs, `build.js` does the following:

1. Read every `posts/*.md` file.
2. Strip metadata lines and frontmatter before Markdown rendering.
3. Preprocess some HackMD-style syntax:
   - code fences like ```` ```lang! ````
   - `:::spoiler`
   - some bare LaTeX block environments
4. Render Markdown to HTML with:
   - `marked`
   - `highlight.js`
   - `marked-katex-extension`
5. Inject the rendered article into `templates/writeup-template.html`.
6. Inject title, date, category, tags, and summary into the hero area when frontmatter exists.
7. Write generated HTML beside the source Markdown file in `posts/`.
8. Regenerate `categories/writeup.html`.
9. Copy vendor CSS/font assets into `assets/vendor/`.

## 5. What is automatic vs manual

Automatic:

- `posts/*.html` generated from `posts/*.md`
- `categories/writeup.html`
- vendor assets copied into `assets/vendor/highlight` and `assets/vendor/katex`

Manual:

- `index.html`
  - especially the `Latest Posts` section
- category landing pages other than the generated writeup listing, unless build support is added later
- tag index pages and tag-specific navigation, which are currently static/manual
- overall site styling and layout templates

Important: adding a new writeup Markdown file is not enough to update the homepage. If you want the new article to appear in `Latest Posts`, you must edit `index.html` manually.

## 6. Writeup naming convention

For writeups, use filenames starting with:

```text
writeup-*.md
```

Reason:

- `build.js` uses the `writeup-` prefix to decide what belongs in `categories/writeup.html`.

If a post does not start with `writeup-`, it will still be built into HTML, but it will not automatically appear in the Writeup category page.

## 7. Markdown authoring guidance

- Prefer block math with `$$ ... $$`.
- Do not assume inline math `\\(...\\)` will render cleanly in prose. The current renderer handles block math more reliably than inline math.
- Keep code fences explicit with a language name when possible.
- If using frontmatter, keep it valid and minimal.

For writeups, a practical pattern is:

```md
---
date: 2026-07-13
summary: One-line summary.
tags:
  - crypto
  - lattice
---

# Challenge Title
```

## 8. Safety notes for future agents

- This repository may have a dirty worktree. Do not revert unrelated user changes.
- Generated HTML files are part of the deployed site. If you change Markdown or `build.js`, rebuild before finishing.
- After rebuilding, inspect diffs in generated HTML for accidental churn.
- The homepage and generated category page can easily go out of sync because one is manual and one is automatic.

## 9. Verification checklist

When changing content or build logic, verify at least:

1. `node --check build.js`
2. `npm run build:n1ctf`
3. The new/updated article HTML exists in `posts/`
4. `categories/writeup.html` contains the new writeup when expected
5. `index.html` is updated manually if the homepage should show the new post
6. Local links still resolve

## 10. Publish model

This site is served from GitHub Pages at:

- `https://nhan-laptop.github.io`

Local file changes do not affect the live site until they are:

1. committed
2. pushed to `origin/main`
3. published by GitHub Pages

If a local page looks correct but the live site does not, first check whether the relevant generated files and manual homepage edits were actually committed and pushed.
